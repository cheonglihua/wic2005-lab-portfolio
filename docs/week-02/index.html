My network

My network is a core/access tree: s1 connects s2 and s3. h1, h3, and h5 attach to s2; h2, h4, and h6 attach to s3. Traffic from h1 to h2 follows h1 → s2 → s1 → s3 → h2. The tree has no Layer 2 loops. Both access groups share the same bridged network; they are not separate VLANs.

Data model and serialization

The switches, hosts, addresses, and links form the network's data model. topology.yaml and topology.json represent the same structure and values. Converting to JSON loses YAML comments and the original formatting, not the meaning of the network.

What the evidence shows

pingall checked IPv4 reachability and received all 30 directed tests (6 × 5); the recorded IPv6 ping from h1 to h2 is a separate single test. In neigh.txt, 10.3.0.2 and fd00:4903::2 both resolve to h2's MAC 86:f8:ac:c0:8a:8f: ARP learned the IPv4 mapping and IPv6 Neighbour Discovery learned the IPv6 mapping. In macs.txt that MAC is on s1 port 2, the link from s1 to s3, which leads toward h2. The switch learns source MAC addresses from frames. dad.txt shows the duplicate IPv6 address fd00:4903::1 as dadfailed tentative, while IPv4 accepts 10.3.0.1 as a secondary address. Duplicate addresses can still produce successful pings, so pingall cannot prove that addresses are unique. Pre-build validation reports both duplicate addresses and the link to missing s9. One successful IPv6 ping does not establish IPv6 all-pairs connectivity.

Why Git diff helps

git diff displays the exact topology changes for review. Commits preserve the history of how the network evolved. That is clearer than keeping ambiguous copies in folders named topology-v2-final.
