My network

I designed a small dual-stack campus lab network. s1 is the core bridge; s2 serves the workshop hosts and s3 serves the services hosts. Three hosts attach to each access switch, and h1-to-h2 traffic crosses the core. The tree keeps every host connected without adding a Layer 2 loop.

Data model and serialization

The data model is the meaning of the network description: its switches, hosts, addresses, and links. YAML and JSON are two serializations of that same model. The JSON file keeps the structure and values but does not carry YAML comments, and its punctuation makes it less convenient to annotate.

What the evidence shows

The IPv4 neighbour entry is learned through ARP, while the IPv6 neighbour entry is learned through Neighbour Discovery. The bridge learns source MAC addresses on its ports. The checker is better than relying on pingall because it identifies duplicate addresses before the network is built; pingall only shows that some paths may be wrong. IPv6 Duplicate Address Detection marked the copied address dadfailed, while IPv4 accepted its duplicate. The checker also rejects links to nodes that do not exist.

Why Git diff helps

git diff shows the exact changes to the structured topology between versions, so I can review and commit each meaningful network change. It also preserves a history of how the network evolved instead of relying on ambiguous copies with names such as final or final-v2.
