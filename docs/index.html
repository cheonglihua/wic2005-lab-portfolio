WIC2005 Programmable Networks

Week 1: Why Programmable Networks Exist

Ethernet connectivity in Mininet, with no controller and no manual switch configuration.

Repository · Markdown write-up · Results transcript

Goal and topology

I built a three-host network on one ordinary Linux bridge. The purpose was to observe the data plane learning source MAC addresses and forwarding frames without an SDN controller.

Reproducibility

Requirements are Docker Desktop or Docker Engine and PowerShell (or a compatible shell). From the repository root:

.\week-01\run_lab.ps1

The script uses the pinned image firdaussahran/netlab-mininet:1.0, runs the topology and observations, and saves the transcript to week-01\results.txt. Its HTTP test serves only week-01/web/, not the repository directory.

Address resolution and bridge learning

After the h1-to-h2 ping, h1's ARP neighbor table maps 10.0.0.2 to 00:00:00:00:00:02. The bridge table after that ping contains all three configured host MAC addresses on ports 1, 2, and 3, including h3. The earlier table contains local bridge interface MAC entries. These two snapshots do not establish exactly when the bridge learned h3's address. ARP maps an IP address to a MAC address on a host; the bridge separately learns source MAC addresses and ingress ports from Ethernet frames.

What it shows

Disconnecting h3 causes checks to and from h3 to fail while h1 and h2 remain connected. Restoring the link returns all six ping checks to success. A Python HTTP server on h2 also responds to curl from h1, confirming application traffic crosses the bridge.

The bridge and host interfaces forward traffic in the data plane. There is no separate SDN control plane or controller in this topology. Mininet creates the network, while the Mininet CLI provides the student's management interface for observations and link changes. Basic Ethernet learning suits this small LAN; programmable control can help automate consistent policy across larger networks.

The committed results transcript records the successful run and the dedicated HTTP test page. Docker may also print resource-limit and bridge-nf-call warnings.
